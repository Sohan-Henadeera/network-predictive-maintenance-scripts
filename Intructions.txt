Raspberry Pi Network Monitoring — Setup Guide (Final)
One repo, two roles. Collector Pis (Pi_1–Pi_4) run collector.py, scanning every 10 seconds and pushing accumulated data into InfluxDB every 30 seconds. Database Pi (Jacob's) hosts InfluxDB + Grafana and never runs the collector.

There is no separate anomaly-collection phase or script — one collector, one cadence, for every device.

Part 1 — Collector Pi Setup (Pi_1, Pi_2, Pi_3, Pi_4)
Run this whole part on every collector Pi, one at a time. Steps 7 and 8 are the only ones that differ per device.

1. Prerequisites
Raspberry Pi running Raspberry Pi OS, connected to the lab router/switch (Ethernet preferred over WiFi for consistent throughput readings)
The Pi's IP address or hostname — check the router's DHCP client list, or run hostname -I on the Pi with a screen attached
The Database Pi's IP address already set up and reachable (see Part 2) — you need this before configuring collectors
2. Log into the Pi
ssh pi@<pi-ip-or-hostname>.local
Enter the Pi's password when prompted.

3. Confirm Python is available
python3 --version
4. Install system-level tools
sudo apt update && sudo apt install -y git arp-scan nmap python3-full
5. Clone the repository
cd ~
git clone https://github.com/Sohan-Henadeera/network-predictive-maintenance-scripts.git
cd network-predictive-maintenance-scripts
6. Set up the Python virtual environment and dependencies
python3 -m venv influx-env
source influx-env/bin/activate
pip install -r requirements.txt
pip install influxdb-client
Reactivate the environment on future logins with source influx-env/bin/activate.

7. Configure this Pi's identity and network targets
nano scripts/collector.py
Edit these values for this specific Pi:

DEVICE_NAME — "Pi_1", "Pi_2", "Pi_3", or "Pi_4" (must be unique per device)
INTERFACE — "eth0" or "wlan0" depending on connection type
PING_TARGETS — the router IP and the other Pis' IPs on this network
To find the router's IP if you don't already have it:

ip route | grep default
Save with Ctrl+O, Enter, Ctrl+X.

8. Configure the InfluxDB connection
In the same file, set the Influx connection block:

INFLUX_URL = "http://<database-pi-ip>:8086"
INFLUX_TOKEN = "<influx-api-token>"       # from Part 2, step 7 — never commit this to git
INFLUX_ORG = "Capstone Group 25"
INFLUX_BUCKET = "pi_1"                     # one bucket per device, matches DEVICE_NAME
Each Pi writes to its own bucket, named after its device (pi_1, pi_2, etc.), created ahead of time on the Database Pi.

9. Run the collector
sudo python3 scripts/collector.py
A new Scan #N block prints every 10 seconds. Every 3rd scan (~30 seconds) you'll see a [influx] pushed N points line — that's the batch landing in the database. Leave it running for the full collection window, stop with Ctrl+C.

To keep it running after closing the SSH session:

nohup sudo python3 scripts/collector.py > collector.log 2>&1 &
10. Verify data is landing (from this Pi)
tail -20 collector.log
Confirm scans are printing AND you're seeing [influx] pushed lines roughly every 30 seconds, not [influx] push failed.

11. Local CSV backup (optional)
The script still writes every scan to Data/normal.csv locally, independent of the Influx push. If you want to check it manually:

cat Data/normal.csv
Readable table view:

column -s, -t Data/normal.csv | less -S
This file stays on the Pi — nothing pushes it anywhere automatically.

Part 2 — Database Pi Setup (Jacob's Pi, one-time only)
This Pi does not run the collector script. It hosts InfluxDB and Grafana for the four collector Pis to write into and for the team to query.

1. System overview
InfluxDB OSS 2.x — time-series database, web UI on port 8086
Grafana — dashboarding tool, web UI on port 3000
Both run locally on this Pi and are reachable from any device on the same network using the Pi's IP.

2. Find this Pi's IP address
hostname -I
Share this IP with the team — it's what every collector Pi points at in Part 1, step 8.

3. Access the web interfaces
InfluxDB: http://<this-pi-ip>:8086
Grafana: http://<this-pi-ip>:3000 (default login admin / admin, you'll be prompted to change it)
4. Manage InfluxDB
sudo systemctl start influxdb
sudo systemctl stop influxdb
sudo systemctl enable influxdb    # auto-start on boot
sudo systemctl status influxdb
5. Manage Grafana
sudo systemctl start grafana-server
sudo systemctl stop grafana-server
sudo systemctl enable grafana-server
sudo systemctl status grafana-server
6. Create one bucket per collector Pi
In the InfluxDB UI (Data → Buckets → Create Bucket), create pi_1, pi_2, pi_3, pi_4 — matching each collector's DEVICE_NAME. Separate buckets per device make it trivial to isolate a faulty Pi's data later without filtering.

7. Generate an API token
Data → API Tokens → Generate Token — give it write access to all four buckets. Copy it into each collector Pi's INFLUX_TOKEN field (Part 1, step 8). Treat this token like a password — don't paste it into chat, commit it to the repo, or leave it in shared docs.

8. Connect Grafana to InfluxDB
In Grafana: Configuration → Data Sources → Add InfluxDB

URL: http://<this-pi-ip>:8086
Query language: Flux
Organisation: Capstone Group 25
Token: the token from step 7
Bucket: set per dashboard panel, or one panel per Pi bucket
Click Save & Test.

9. Moving this Pi to a different network
Only the IP changes. Re-run hostname -I, then update every collector Pi's INFLUX_URL in Part 1, step 8. All buckets, dashboards, and tokens carry over untouched.

10. Safe shutdown
sudo shutdown now
or

sudo poweroff
Wait for the green LED to stop blinking before unplugging power.

Quick reference
Task	Command
Check Pi's IP	hostname -I
Find router IP	ip route | grep default
Run collector (foreground)	sudo python3 scripts/collector.py
Run collector (background)	nohup sudo python3 scripts/collector.py > collector.log 2>&1 &
Check collector's live log	tail -20 collector.log
View local CSV backup	column -s, -t Data/normal.csv | less -S
Start/stop InfluxDB	sudo systemctl start|stop influxdb
Start/stop Grafana	sudo systemctl start|stop grafana-server
Shut down safely	sudo shutdown now
